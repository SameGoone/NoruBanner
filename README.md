_**1. Заработает ли мой код, если на странице два баннера?**_

Добавляем bannerId в пропсы компонента Banner. Теперь каждому баннеру можно задавать свой идентификатор и добавлять их на страницу в любом количестве.

**_2. Как можно идентифицировать пользователя сайта с баннером?_**

**_А если сайтов будет несколько?_**

Идентификация на одном сайте:

Я решил использовать localStorage для хранения уникального ID пользователя. localStorage сохраняется в браузере между сессиями. Пока пользователь не очистит кеш браузера вручную, ID будет постоянным. Это решение **не** позволяет идентифицировать пользователя между сайтами.

Альтернативы:

- First-Party Cookies: автоматически отправляются на сервер с каждым HTTP-запросом.

Идентификация на нескольких сайтах:

- Third-Party Cookies - блокируются современными браузерами

- Фингерпринтинг - подпадает под GDPR/ePrivacy, требует оптимальной настройки по точности, но никогда не даст 100% результат

- Авторизованных пользователей можно однозначно идетифицировать, вне зависимости от браузера и домена.

С кросс-сайтным отслеживанием всё непросто и требует компромиссов. 

_**3. Какие ограничения у события "увидел баннер"? Работает ли это во всех браузерах?**_

_**Можно ли придумать иные технические решения этой проблемы?**_

Ограничения события "увидел баннер":

- Какая часть баннера должна быть в области видмости? В моей реализации 100%, можно настроить через threshold для IntersectionObserver

- Сколько времени пользователь должен смотреть на баннер? В моей реализации это происходит мгновенно при достижении 100% области видимости, можно добавить setTimeout.

- Есть вероятность, что IntersectionObserver сгенерит событие обзора даже на неактивной вкладке. Хотя в современных браузерах используются оптимизации при сворачивании, они не всегда могут отрабатывать как ожидается, поэтому я добавил проверку document.visibilityState

- IntersectionObserver может не поддерживаться старыми браузерами (например Explorer или старые версии Safari), поэтому для старых браузеров нужно использовать устаревший подход с подпиской на scroll и ручным расчётом положения элемента

4. Дополнительные ограничения

- При получении события я не проверяю, что данный пользак уже видел/кликал на этот баннер. Предполагается, что выборкой из БД можно отсеять уникальные записи. Но в зависимости от нужд, можно проверять что событие от данного пользака уже зарегистрировано. Также можно проверять при событии Click, что существует событие View, и менять ему тип. Это сэкономит место в БД, но лишит данные подробностей.
